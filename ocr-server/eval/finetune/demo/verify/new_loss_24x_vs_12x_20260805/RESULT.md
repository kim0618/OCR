# 12배 → 24배 신규 손실 668장 판독

## 대상

- 12배 스캔: `260804_1623`
- 24배 스캔: `260805_1341`
- 최종 검수 GT에서 12배는 정답, 24배는 오답으로 바뀐 크롭: **668장**
- 원본 구성: `crops/` 254장 + `crops_correct/` 414장
- 원본 경로: `paths_668.txt`
- 전체 메타데이터: `audit_668.json`, `audit_668.tsv`
- 층화 표본: `sample_50.json`, `sample_sheet_1.png`~`sample_sheet_5.png`

## 판독 방법

1. 668장 전부에 최종 reviewed GT, 12배 출력, 24배 출력을 연결했다.
2. 문자열 변화 형태를 기호·괄호·회사표식·한 글자·복합 오류로 전수 분류했다.
3. 기호/괄호/`㈜↔(주)` 층을 과대표집하고 실제 글자 오류도 포함한 50장을 시트로 만들어 크롭 실물을 직접 읽었다.
4. 상품명 본체는 첫 `/`, `(`, `[` 앞의 영숫자·한글 문자열로 근사해 본체 보존 여부를 전수 분해했다. 이 수치는 제품명 본체/부가표기의 근사 분류이며 GT exact 판정 자체는 아니다.

표본 50장에서는 잘못 연결된 이미지나 명백한 GT 오류를 발견하지 못했다. 24배 출력에서 `/`, `//`, `-`, 괄호, `(주)`의 닫는 괄호, 한글 한 글자 등이 실제로 빠지거나 바뀐 것이 크롭에서 확인됐다.

## 12배와 24배 최종 비교

최종 GT 217장 수정·3장 제외 및 전체 제외 정책을 동일하게 적용한 45,356크롭 기준이다.

| 모델 | 정답 | base 대비 잃음 | base 오답 되살림 | 순증 |
|---|---:|---:|---:|---:|
| 12배 | 37,741 | **593** | 7,608 | +7,015 |
| 24배 | **37,973** | 691 | **7,938** | **+7,247** |

12배 → 24배 직접 전환:

- 12배 정답 → 24배 오답: 668
- 12배 오답 → 24배 정답: 900
- 전체 exact 순개선: **+232**
- 신규 손실 중 상품명 본체 변화: 337
- 신규 회복 900장 중 12배에서 상품명 본체가 틀렸던 사례: 670

즉 24배는 전체 정답과 상품명 본체 회복량은 늘었지만, base가 맞던 항목을 보존하는 안정성은 나빠졌다. base 대비 실제 잃음이 593→691로 **98장 증가**했다.

## 결론

사전에 정한 24배 채택 조건 중 `실제 잃음 < 593`을 충족하지 못했다. 668장 중 절반가량이 기호·부가표기 층이지만 나머지 337장은 상품명 본체 오류라서 신규 손실을 무시할 수 없다.

따라서 **회귀 억제와 기존 정답 유지가 채택 기준이면 12배를 유지**하는 것이 맞다. 24배는 전체 exact 정답 +232와 본체 회복 순증을 만들었으므로 전체 인식량만 우선하면 이점이 있지만, 기존 합의한 안전 게이트에는 실패했다.
