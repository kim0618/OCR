## 24배 실험 설계

다른 조건은 12배와 동일하게 고정한다.

- 시작 가중치: official `korean_PP-OCRv5_mobile_rec`
- 타깃: `세파록스캡슐`
- 타깃 학습 크롭: 167장
- 앵커: **4,008장** (`167 × 24`)
- 전체 train 예상: 4,175장
- 복제: 없음
- 앵커 구성: 현재 품명/짧은 숫자/나머지 혼합 정책 그대로
- epoch: 20
- learning rate: 3e-5
- batch: 64
- seed, val, 판정 크롭, GT override/exclude 정책 모두 동일
- 예상 시간: 기존 기록 기준 약 50분

실제 AWS 실행 명령은 AWS의 최신 `run-finetune` 스크립트와 인자를 먼저 확인해서 제시한다. 로컬에 없는 명령을 추정해서 만들지 않는다. 사용자 메모리 규칙에 따라 학습 실행은 사용자가 한다.

## 24배 이후 1차 2단계

현재 두 번째 타깃 1순위 후보는 `아르티스F정`이다.

- 기준 크롭 10장 중 9장 오독
- 대표 오독은 `아르티스정` 9장으로 `F` 한 글자가 일관되게 누락
- 제조사 괄호나 단순 띄어쓰기 문제가 아니라 상품명 본체 오류

AWS 코퍼스에서 먼저 학습 가능한 비기준셋 크롭 수를 `eval/demo_corpus_count.py`로 확인한다. 학습량이 충분하고 이미지/GT가 정상임을 확인한 뒤 선택한다. 선택되면 확정 부모 모델 위에서 `세파록스캡슐 + 아르티스F정`을 누적 학습하고 두 품명 모두 동일 판정셋에서 유지되는지 본다.

## 크롭 썸네일이 사라졌던 원인과 조치

- GT 교정 후 후보를 새 품명으로 다시 묶었지만 기존 `NEXT_TARGETS.json`의 썸네일을 품명 문자열 일치로만 재사용해 이름이 바뀐 그룹의 연결이 끊겼다.
- 원본 이미지가 삭제된 것은 아니다.
- `recount_reviewed_gt.py`를 수정해 감사 압축본 `lost_crops.tgz`의 파일 해시와 스캔 경로를 연결한다.
- 감사 압축본에 없는 항목은 각 경로의 원래 GT를 통해 기존 캐시 썸네일을 보완한다.
- 최종 잃어버림 후보 477개 품명은 전부 이미지가 연결됐다.
- 못 읽음 후보는 전체 원본이 로컬에 없으므로 기존 캐시가 있는 일부만 이미지가 있다. 전체 원본은 AWS 코퍼스 쪽이다.
