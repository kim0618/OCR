거래명세서 LEARN-LOOP 인프라(Phase 0~5 완료)에서, 사용자가 베이스셋을 돌려보려는 의도는 **"수천 장 학습 전에 이 학습 시스템이 유효한가/가능성이 있나"를 가늠하는 probe**다. **베이스셋을 GT에 완벽히 맞추는 것이 목표가 아니다.**

**⚠️ 단위 정정(2026-06-16):** 평가 베이스는 **24 이미지**다. "6"은 GT-검증된 *distinct 문서/레이아웃*(1·3·4·5·6·7) 수이고, 각 문서의 각도변주(1-1,1-2,1-3…)를 더해 24가 됨. **레이아웃 다양성=6, 각도 강건성 표본=24.** "6장"이라고만 쓰면 변주를 빼먹는 것 — run은 24장을 돈다(run 034 확인).

**Why:** 사용자가 "6개 완벽히 맞추자는 게 아니잖아, 수천장 가능성을 보려는 거잖아"라고 두 번 정정함(한 번은 tool use 거부까지). 내가 자꾸 "지금 주소 노이즈 룰 고치자"는 실행 액션으로 몰아서 어긋남. 사용자는 루프 **개념을 이해·확인**하려는 단계였고, 긴 caveat 반복이 아니라 간결한 확정을 원함.

**How to apply:**
- 루프 개념("돌림→약점 나옴→보강→재측정→좋아지나")을 사용자가 확인하려 하면 **간결히 "맞다"** 하고, 긴 표/caveat 반복하지 말 것.
- probe로 알 수 있는 것 = ① 기계가 도는가 ② 룰로 칠 수 있는 에러(구조) vs 못 치는 것(OCR 인식) 비중(6장 기준 구조14:인식39 ≈ 1/4만 룰 가능). probe로 못 보는 것 = 일반화(holdout 필요)·실제 정확도 천장(수천장 몫).
- 회전/전처리 약점은 "측정 O, 보강 X(OCR 락)" **한 줄로만** 구분. 구조/룰 쪽만 실제 보강 루프가 돎.
- 실제 룰 수정은 사용자가 명시적으로 "고치자" 할 때만. 먼저 묻지 말고 probe 해석·다음 선택지를 제시하는 선에서.
